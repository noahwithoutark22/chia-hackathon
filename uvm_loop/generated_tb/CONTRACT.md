|---------|---------|-----------|-------|------------|--------------|

| Reset   | `rst_n` | input     | 1     | async      | **active-low** |

**Reset behavior:**
- Asynchronous assertion: on the falling edge of `rst_n` (independent of
  clock), `sum` and `cout` are immediately cleared to zero.
- Synchronous (or async) de-assertion: when `rst_n` returns high, normal
  registered operation resumes on the next `posedge clk`.

## 8. Notes for Later Stages

- **Driver:** Use `DUTHelper.set_inputs()` after `RisingEdge(clk)` to
  present inputs for the next cycle.
- **Monitor:** Use `DUTHelper.sample_outputs()` after `ReadOnly()` or
  one clock edge after inputs are driven to capture registered outputs.
- **Scoreboard:** Call `adder_ref(a, b, cin, width)` and compare against
  `(exp_sum, exp_cout)` from the transaction.
- **Coverage:** Use `cocotb-coverage` `CoverPoint` to sample `a`, `b`,
  `cin`, `sum`, `cout` value combinations.
- **Watchdog:** Always start a watchdog coroutine at test start; fail
  the test if it does not complete within a bounded number of clocks.

### 13.3 Top-level entry point (`test_top.py`)

- Reads `UVM_TESTNAME` (default `AdderFullRegressionTest`), matching SV
  `+UVM_TESTNAME`.
- Starts `cocotb.clock.Clock` on `dut.clk`; drives inputs to zero; asserts,
  holds, and releases the active-low async reset via `DUTHelper.reset_dut`.
- Populates the Section 6 ConfigDB keys via `ConfigDB().set(None, "", key, ...)`.
- Calls `uvm_root().run_test(name, keep_singletons=True)`:
  **`keep_singletons=True` is required** because pyuvm's `run_test` clears
  the `ConfigDB` singleton by default, which would wipe the keys this tb_top
  establishes before building the components.
- Wraps the UVM run in `cocotb.triggers.with_timeout(..., WATCHDOG_CYCLES
  * CLK_PERIOD_NS, "ns")` so a hung run fails the test within a bounded
  number of clock cycles.

### 13.4 Deterministic input/output correlation (fix applied in Stage 6)

During the integration consistency pass the Stage-3 monitor and Stage-5
arithmetic assertion were found to correlate *current-cycle* inputs with
*previous-cycle* outputs by sampling inputs at the same `RisingEdge` region
where the driver updates inputs — an ordering-sensitive race that could
publish a misaligned (false-mismatch) transaction.  **Fix:** inputs are now
sampled at the `FallingEdge` (mid-cycle), where they are guaranteed settled,
and paired with the registered outputs at the next `RisingEdge`+`ReadOnly`.
Observable behavior is unchanged (same fields, 1-cycle latency); only the
sampling point is made deterministic.

### 13.5 Reset-aware publishing (fix applied in Stage 6)

During reset assertion the DUT outputs are forced to zero by the async
reset (Section 2), not by the addition, so they cannot be validated against
`adder_ref`.  The monitor now **skips publishing** while `rst_n` is low;
reset-clearing behavior is instead verified by the assertion checkers
(`reset_clears_sum` / `reset_clears_cout`).  This prevents the scoreboard
from raising false mismatches on the `reset_clears_outputs` scenario.
